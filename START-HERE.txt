ADDING A WEEK 3 LESSON
  1. Copy lessons/_template.js to lessons/week3/w3d1.js and write the content.
  2. New readings/listening go in lessons/week3/sources.js.
  3. In lessons/course.js set the day to status: 'ready' and list its scripts.
  4. Raise the version (?v= in index.html and version in js/config.js).

tables), figure (pictures and diagrams), and gate: '…' on a passage to hide a sample text until the
student has written their own version.

HOW A PAGE IS BUILT
Each activity is a list of blocks. Each block type always looks the same:
  KEY POINT (dark navy box, gold edge)  the one idea to learn — the most prominent element
  What to do                            numbered steps with an Alone / Pair / Group / Whole class badge
  Speak (purple)                        discussion prompts
  Language bank (blue)                  phrases grouped by function
  Model (green, dashed)                 a worked example
  Teacher note (amber, dashed)          visible only in Teacher view
  Suggested answers (green)             open after the student has tried; always open in Teacher view
Headings: H1 = stage, H2 = activity, H3 = block.
The block types are listed in lessons/_template.js.

TEACHER VIEW
The "Teacher view" switch at the bottom of the sidebar shows all teacher notes and suggested answers.
Set the default for new browsers with teacherView in js/config.js.

SAVING — DEVICE + ONLINE (SUPABASE)
Every change is saved on the device first. When a student signs in (top bar: "Sign in to save
online"), the same work is also saved to Supabase about one second later and appears on any
device where they sign in. Device and online copies are merged, so no answer is dropped.
To switch online saving on:
  1. Run supabase/migrations/20261002000000_dec15_progress.sql in your Supabase project.
  2. Put the project URL and the publishable (anon) key in js/config.js. Never use service_role.
  3. Recommended: Authentication > Providers > Email > turn OFF "Confirm email", so students can
     sign in straight away (Supabase's built-in email service only sends a few emails per hour).
  4. Make yourself a teacher with the UPDATE statement at the end of the migration.

UPDATES KEEP STUDENT WORK
Saved work is stored per lesson under the key "dec15-<lesson id>-v2" (e.g. "dec15-w2d5-v2") and by
field id (e.g. "d3t-0-1", "plan-thesis"). Never change a lesson id or rename an existing id —
then everything students already wrote stays. New activities simply start empty.
Bump ?v= in index.html (and version in js/config.js) on each release so browsers fetch new files.

NOTEBOOK & EXPORTS
My notebook shows all work by stage, with tables and the essay plan kept as tables.
Exports: PDF, Open in Google Docs (copies the notebook, opens a new Doc, student presses Ctrl+V),
Word (.docx, also opens in Google Docs) and Print. Libraries are bundled in js/vendor/ (MIT).

CLASS WALL (v2.7)
Under every activity there is a Class wall. Signed-in students can post a comment or notes, reply,
and react with emojis (👍 ❤️ 👏 💡 🤔 😂). Writing boxes have a "Share with class" button that posts
the student's text to the wall of that activity; their own saved copy does not change.
- Everyone signed in to DEC15 can read the walls; names come from the student's profile.
- Students can delete their own posts. A teacher (profiles.role = 'teacher') can delete any post.
- New posts appear for everyone automatically (Supabase Realtime).
- Turn the wall off for one activity with  wall: false  (or a whole lesson with  wall: false  at the top),
  and the Share button off for a writing box with  share: false.
Database: supabase/migrations/20261006000000_dec15_class_wall.sql (already applied to the project).

NAVIGATION (v2.8)
The side panel lists the whole course: weeks fold open and closed, each lesson shows its progress ring,
and the open lesson shows its stages plus Readings / Extra / Notebook. The search box (press / ) finds
lessons, parts of lessons, stages and activities. On phones the side panel opens with the Menu button.
The course map shows one week at a time (week tabs); click a week on the map to open its lessons.
Notebook stages fold open and closed; busy class walls show the newest 3 posts (and 2 replies) first.

ORDERING ACTIVITIES (v2.10)
"Put in order" activities (block type  order ) now work by drag and drop: hold the mouse button on a card
and drag it up or down; the other cards slide out of the way. On phones, drag by the dotted grip on the left.
The arrow buttons still work, and keyboard users can select a card, press Space, move it with the up/down
arrows and press Space again. After "Check my order", correct cards show a tick and wrong cards say which
position they belong in; students can try again or show the correct order.

CREATING ACCOUNTS (v2.11) — IMPORTANT SETTING
Students saw "Too many attempts" because Supabase's built-in email service sends only a few emails per hour
for the whole project, and with "Confirm email" switched on every new account needs an email.
Fix (once, 1 minute): Supabase dashboard → Authentication → Sign In / Providers → Email →
switch OFF "Confirm email" → Save. Students can then create an account and are signed in straight away.
Also check Authentication → URL Configuration: Site URL = https://ma-jalali.github.io/dec15b/
(If you want to keep email confirmation, add your own SMTP server under Authentication → Emails → SMTP.)
The sign-up form now checks the email and password before sending, keeps what students typed after an error,
has a Show password button, and explains clearly when the email service is busy.

NO-EMAIL SIGN-UP (v2.12)
New accounts are now created by the Supabase Edge Function "dec15-signup"
(supabase/functions/dec15-signup/index.ts, already deployed). It creates the account already confirmed,
so no email is sent and the email limit can no longer block a class; the student is signed in at once.
The admin (service-role) key stays inside Supabase — it is never in the website code.
If the function cannot be reached, the app falls back to the normal sign-up (which still needs the
"Confirm email" setting above). Turning "Confirm email" off is still recommended as a backup.
