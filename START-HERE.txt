HOW A PAGE IS BUILT
Each activity is a list of blocks. Each block type always looks the same:
  KEY POINT (dark navy box, gold edge)  the one idea to learn — the most prominent element
  What to do                            numbered steps with an Alone / Pair / Group / Whole class badge
  Speak (purple)                        discussion prompts
  Language bank (blue)                  phrases grouped by function
  Model (green, dashed)                 a worked example
  Teacher note (amber, dashed)          visible only in Teacher view
  Suggested answers (green)             open after the student has tried; always open in Teacher view
Headings: H1 = stage, H2 = activity, H3 = block.
The block types are listed in lessons/_template.js.

TEACHER VIEW
The "Teacher view" switch at the bottom of the sidebar shows all teacher notes and suggested answers.
Set the default for new browsers with teacherView in js/config.js.

SAVING — DEVICE + ONLINE (SUPABASE)
Every change is saved on the device first. When a student signs in (top bar: "Sign in to save
online"), the same work is also saved to Supabase about one second later and appears on any
device where they sign in. Device and online copies are merged, so no answer is dropped.
To switch online saving on:
  1. Run supabase/migrations/20261002000000_dec15_progress.sql in your Supabase project.
  2. Put the project URL and the publishable (anon) key in js/config.js. Never use service_role.
  3. Recommended: Authentication > Providers > Email > turn OFF "Confirm email", so students can
     sign in straight away (Supabase's built-in email service only sends a few emails per hour).
  4. Make yourself a teacher with the UPDATE statement at the end of the migration.

UPDATES KEEP STUDENT WORK
Saved work is stored per lesson under the key "dec15-<lesson id>-v2" (e.g. "dec15-w2d5-v2") and by
field id (e.g. "d3t-0-1", "plan-thesis"). Never change a lesson id or rename an existing id —
then everything students already wrote stays. New activities simply start empty.
Bump ?v= in index.html (and version in js/config.js) on each release so browsers fetch new files.

Students saw "Too many attempts" because Supabase's built-in email service sends only a few emails per hour
for the whole project, and with "Confirm email" switched on every new account needs an email.

switch OFF "Confirm email" → Save. Students can then create an account and are signed in straight away.

(If you want to keep email confirmation, add your own SMTP server under Authentication → Emails → SMTP.)

has a Show password button, and explains clearly when the email service is busy.

NO-EMAIL SIGN-UP (v2.12)
New accounts are now created by the Supabase Edge Function "dec15-signup"
(supabase/functions/dec15-signup/index.ts, already deployed). It creates the account already confirmed,
